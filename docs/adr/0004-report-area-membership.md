# ADR-0004: 신고 대상 지역 판정에서 시·군·구가 시·도에 속하는지 판단하는 방법

> 상태: 승인 (2026-11-12, 사용자 답 "승인 (Recommended)")
> 날짜: 2026-11-12

## 맥락

- PR #37 리뷰 1 원문(사용자가 그대로 붙여 넣음, PRD 머리글 "PR #37 리뷰 반영"에서 인용): "지역 선택 이벤트에서 시·도만 바꾸면 `S.sgg`는 초기화되지만 `S.gu`는 이전 값을 유지할 수 있습니다. 새 `reportArea(S.sido, S.gu)`가 이 조합을 사용하므로 잘못된 지역 판정이 발생할 수 있습니다. 지역 변경 시 상태를 일관되게 정리하고, 시·군·구 미선택 및 서로 다른 지역 값이 섞인 상태에 대한 테스트를 추가해 주세요."
- PRD F-02 ② 2026-11-12 추가분: 그 밖의 도(충북·충남·경북·경남)와 강원·전북·전남광주통합에서 시·군·구가 비었거나 "그 시·도에 속하지 않는 값(예: 경상북도 + 서울 구 이름)"이면 확인 필요(required=null).
- 현재 `demo/engine.js` 79~86행 `reportArea`는 `/군$/`만 본다 — 빈 값이나 다른 시·도의 구 이름도 '군이 아님'으로 보아 inArea true.
- 제약: `reportArea(sido, gu)` 입력 규격과 `deadlines(S)` 호출부(`demo/app.html` 1233행 `JE.deadlines(S)`)는 바꾸지 않는다(메인 세션 제안 조건). engine.js는 순수 함수이고 의존 대상 "없음"(Architecture 모듈 경계 표).
- 데이터 사실(architect가 `demo/data/regions.js` 4행에서 직접 확인, 2026-11-12):
  - 충북 14·충남 17·경북 23·경남 22·강원 18·전북 15개 시·군·구 이름은 모두 `~시`, `~군`, `~시 ~구` 형태다.
  - **전남광주통합특별시 27개 중 5개는 `동구`·`서구`·`남구`·`북구`·`광산구`(코드 12210~12330, 옛 광주광역시 자치구)로 `~시 ~구` 형태가 아닌 단독 `~구`다.**
  - `고성군`은 경상남도(48820)와 강원특별자치도(51820) 두 곳에 있다.
- 이전 버전에서 저장된 상태가 남아 있을 수 있다: 리스너 수정(T-21 ①) 전에는 충청북도 보은군을 고른 뒤 시·도를 경상북도로만 바꾸면 `S.sido = '경상북도'`, `S.gu = '보은군'`이 저장된다(`demo/app.html` 1957·1959행). 리스너를 고쳐도 이미 저장된 값은 남는다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 이름 형태 규칙(메인 세션 제안): 이 시·도들에서 `/(시\|군)$/`·`/시 \S+구$/`에 맞지 않으면 '시·도와 시·군·구가 맞지 않음' null, 빈 값은 '시·군·구를 아직 고르지 않음' null | 입력 규격·의존 불변, 코드 몇 줄 | ① 전남광주통합특별시의 광주 5개 구(`광산구` 등)가 형태 규칙에 걸려 null — T-18에서 대상(true)이던 실제 지역이 '확인 필요'로 바뀌는 회귀(기존 테스트는 이 경우를 다루지 않아 잡히지 않음). 이를 피하려고 전남광주만 단독 `~구`를 허용하면 `전남광주통합특별시 + 관악구`가 다시 true ② 형태가 맞는 다른 시·도 값은 못 잡음: `경상북도 + 보은군`(충북) → false('경상북도 보은군 소재'라는 틀린 이유), `강원특별자치도 + 보은군` → null이지만 이유가 다름, `경상북도 + 천안시` → true. 위 '이전 저장 상태'가 바로 이 경우라 실제로 생긴다 ③ PRD F-02 ② "그 시·도에 속하지 않는 값"을 서울 구 이름 예시에만 충족 |
| B. engine.js가 실행 중 `demo/data/regions.js`를 읽음(브라우저 `window.JACHWI_REGIONS`, Node `require('./data/regions.js')`) | 지역 목록 원본 하나, 소속을 정확히 판단 | engine.js 의존 "없음" → 다른 팀원 데이터 파일 의존으로 바뀜, 순수 함수가 전역을 읽음, 목록이 없을 때(스크립트 실패)의 별도 분기 필요, 브라우저 `defer` 순서(engine.js 18행이 regions.js 20행보다 먼저)에 기대는 호출 시점 가정 |
| C. engine.js 안에 7개 시·도(AREA_DO + AREA_UNSURE)의 시·군·구 이름 표를 두고 소속을 판단 + Node 테스트가 이 표와 `demo/data/regions.js`의 같은 시·도 목록이 같은지 검사 | 입력 규격·호출부·의존 "없음" 모두 불변, 순수 함수 유지, 광주 5개 구·`고성군`·다른 시·도 값 모두 정확, 이미 `LAW.seoulGu`(25개)를 같은 방식으로 안에 둠 | 이름 136개를 engine.js에 복사(데이터 중복). regions.js가 바뀌면 테스트가 실패해 알려 주지만 engine.js 표를 손으로 맞춰야 함 |
| D. `reportArea(sido, gu, list)`처럼 목록을 인자로 주입 | 의존 없음, 정확 | 입력 규격 변경, `deadlines(S)`도 목록을 받아야 해 app.html 1233행 등 호출부·`answer-key`·`engine` 테스트 호출까지 바뀜 — 메인 세션 조건(입력 규격 불변) 위반 |

## 결정

C. 결정적 이유: 입력 규격과 engine.js의 "의존 없음"을 지키면서, 형태 규칙(A)이 놓치는 광주 5개 구 회귀와 이전 저장 상태(`경상북도 + 보은군`)를 정확히 판정한다.

판정 순서(AREA_DO·AREA_UNSURE 시·도만, 광역시·경기·세종·제주와 시도 없음·그 밖 시도는 DECISIONS #21 그대로):

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | 시·군·구가 비었거나 공백뿐 | `{ inArea: null, reason: '시·군·구를 아직 고르지 않음' }` |
| 2 | 시·군·구가 그 시·도의 목록에 없음 | `{ inArea: null, reason: '시·도와 시·군·구가 맞지 않음' }` |
| 3 | 목록에 있고 `~군` | DECISIONS #21 ②③ 그대로(일반 도 false, 강원·전북·전남광주 null) |
| 4 | 목록에 있고 그 밖(`~시`, `~시 ~구`, 광주 단독 `~구`) | `{ inArea: true, reason: '' }` |

## 결과 (트레이드오프 포함)

- 얻는 것: `reportArea`·`deadlines` 시그니처, app.html 호출부, `answer-key` 테스트 불변. `전남광주통합특별시 + 광산구` → true 유지. 저장된 섞인 값은 잘못된 '대상 아님' 대신 '확인 필요'로 보인다.
- 감수하는 것: engine.js에 이름 136개 표. `demo/data/regions.js`(지원사업 담당이 만든 데이터)가 행정구역 개편 등으로 바뀌면 일치 검사 테스트가 실패하고, 그때 engine.js 표를 갱신해야 한다(regions.js 수정은 이 결정의 범위가 아님).
- 표는 `JE.reportAreaSgg`(`{ [시·도]: string[] }`)로 내보내 테스트가 regions.js와 비교한다 — engine.js는 regions.js를 읽지 않고, 테스트만 둘 다 읽는다.
- 테스트에 꼭 넣을 경우(T-21 완료 조건 ①②에 해당): 빈 값·공백, 서울 구 이름(`경상북도 + 관악구`), 다른 시·도의 정상 이름(`경상북도 + 보은군` → null, `경상북도 + 천안시` → null), 광주 구(`전남광주통합특별시 + 광산구` → true), 같은 이름 두 시·도(`경상남도 + 고성군` → false, `강원특별자치도 + 고성군` → null), 표·regions.js 일치 검사.
