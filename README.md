# 자취대로

처음 자취하는 청년을 위한 계약·신고·지원 통합 타임라인 웹서비스.
계약 조건과 기본 정보를 넣으면 신고 의무, 신청해 볼 수 있는 지원, 할 일과 기한을 하나의 타임라인으로 안내하고, 입주 뒤에는 주변 탐색·생활비·집 상태 기록·AI 자취 코치까지 이어 준다.

- 이용 대상: 처음 자취방을 계약하는 만 19~39세 대학생·사회초년생
- 운영자: 지원 공고를 등록·검수하고 AI 코치가 쓰는 안내를 관리하는 담당자
- 지역: 전국 시·도, 시·군·구 (전월세 신고 대상 판정, 지원사업 목록 모두)

- 처음 입력을 마친 예시 인물(서울 관악구, 만 24세, 보증금 1,000만·월세 45만, 입주 5일 전 기준으로 가입)로 들어가 있다.
- 집 위치 좌표는 서버에 올리지 않는 원칙이라 기기마다 비어 있다. 주변 탐색을 보려면 '내 계약'에서 집 위치를 한 번 정한다.
- 새로 가입해 처음 입력부터 보려면 로그인 화면의 '회원가입'을 쓴다(인증 메일이 온다).

추천 시연 순서 (5분)

1. 로그인(심사용 계정 또는 회원가입) → 첫 실행 길잡이 → 계약일·입주일, 지역·보증금·월세, 집 위치 입력
2. 자격 판정 → 전월세 신고 대상 여부와 기한, 신청해 볼 지원(조건별 원문 근거)
3. 타임라인 → 계약 전부터 퇴거까지 할 일과 법정 기한
4. 지원사업 → 내 시·군·구의 실제 청년정책·복지서비스·LH 공고, 모르는 조건은 그 자리에서 묻고 판정
5. 주변 탐색 → 카카오 지도에서 집 주변 장소·도보 경로·버스정류장·로드뷰
6. 생활 관리 → 주거비 관리(납부 체크·관리비 포함 설정), 자취 캘린더(일정 알림·휴대폰 캘린더 연동), 집 상태 기록(카메라로 바로 촬영)
7. AI 자취 코치 → 봇 6개(집주인톡·고쳐봇·절약봇·권리봇·동네봇·자유 질문)에 내 계약 기준으로 질문
8. 운영자 콘솔 → 실제 공고문 붙여 넣기 → AI 추출 → 원문 근거 대조 → 승인 → 이용자 화면에 반영, '품질 평가' 탭

## AI 활용 원칙

- **금액·자격·기한 판정은 AI가 아니라 규칙으로만 한다.** 같은 입력이면 항상 같은 답이 나온다.
- AI는 공고문 구조화(항목 추출 + 원문 근거)와 이용자 질문 답변에만 쓴다.
- 공고에서 추출한 내용은 운영자가 원문과 대조해 **승인한 규칙만** 이용자 판정에 반영한다. 초안·메모는 이용자 화면에 나가지 않는다.
- AI 코치는 승인된 지식 카드와 내 계약 값 안에서만 답하고, 맞는 안내가 없으면 답하지 않는다. 답하지 못한 질문은 그 기기에 기록되어 같은 기기의 운영자 콘솔(연습 모드)에서 볼 수 있다. 서버 AI를 켠 경우에만 서버의 '답 못 한 질문'으로 모인다.
- **운영 배포판은 외부 AI를 호출하지 않는다.** 공고 추출과 코치 답변 모두 브라우저 안의 내장 엔진(규칙 추출 + 승인 카드 검색 + 말투 다듬기)으로 동작한다(`/api/rules`의 `ai: false`). 서버에 `ANTHROPIC_API_KEY`(또는 `ANTHROPIC_AUTH_TOKEN`)를 넣으면 같은 시스템 프롬프트로 Claude API를 쓰는 선택 기능이 켜지고, 실패하면 내장 엔진으로 돌아간다.
- 승인 공고 7건은 모두 실제 공고 페이지의 글을 원문으로 둔다. 담당자가 원문에서 항목과 근거 문장을 정리하고, 검수기(근거 문장이 원문에 있는지·숫자·날짜·목록 항목 대조)를 통과시켜 승인본(`demo/rules/seed.js`)에 넣었다. 운영자 콘솔에서 발행한 것이 아니라 승인본 파일에 직접 넣은 것이다. 내장 추출기는 같은 원문에서 114개 항목 중 40개를 그대로 맞힌다.
- 공고문 속 "이전 지시를 무시하라" 같은 문장은 지시로 따르지 않고 검수 메모로 표시한다.

## 개인정보 원칙

- 판정·기한 계산은 브라우저에서 한다. 서버 함수(공공데이터·지도 등)는 이용자 정보를 받지 않는다. 기록은 기기(`localStorage`)에 두고, 로그인한 계정에만 아래 범위로 동기화한다.
- 서버 함수는 이용자 정보를 받지 않는다. 지역 코드·분류만 받고, 서버를 거치는 주변 장소 조회(OpenStreetMap)는 위치를 약 100m 단위로 흐려서 보낸다.
- 신분증·서류 원본은 보관하지 않는다.
- 로그인해서 쓴다(이메일 인증, 카카오, Google). 로그인하면(Supabase Auth) 계약·할 일·주거비 기록만 본인 계정 한 줄(`user_state`)에 저장해 다른 기기에서 이어 본다. 집·통학 위치 좌표, 저장한 장소, AI 대화, 집 상태 사진 기록, 서류는 올리지 않는다(`demo/account-core.js`의 `SKIP`). 본인 줄만 읽고 쓰도록 DB 권한(RLS)을 걸었고, 계정 삭제를 누르면 서버 기록과 계정이 함께 지워진다.
- 기한 알림을 켠 기기는 브라우저 푸시 주소만 계정에 저장한다(`push_subs`, 본인 것만 보고 지움). 알림 내용은 휴대폰 캘린더 구독과 같은 일정 묶음(날짜·금액·일정 제목)에서 만들고, 로그아웃하면 그 기기 알림도 끈다.
- API 키와 운영자 코드는 Vercel 환경변수로만 관리하고 저장소·화면 코드에 넣지 않는다(카카오 지도 JavaScript 키는 도메인 제한이 있는 브라우저용 키라 예외).

## 직접 실행하기

Node 20 이상, 빌드 없음.

```bash
cd demo && node dev-server.js
```

`http://localhost:4173/app.html`(서비스), `http://localhost:4173/admin.html`(운영자 콘솔)로 연다. 공공 API를 쓰려면 저장소 루트의 `.env.example`을 `demo/.env`로 복사해 키를 적는다(`.env`는 `.gitignore`로 제외됨, 예시 파일에는 값 없이 이름만 둔다). 키가 없으면 그 목록만 "불러오지 못했어요"로 나오고 나머지는 그대로 동작한다.

| 환경변수 | 용도 |
|---|---|
| `YOUTH_API_KEY` | 온통청년 |
| `DATA_GO_KR_KEY` | 복지로·LH·특일 (공공데이터포털) |
| `TAGO_API_KEY` | 버스정류장 |
| `KAKAOMAPSDK_KEY`, `KAKAOREST_API_KEY` | 카카오 지도·장소·도보 경로 |
| `ADMIN_TOKEN`, `BLOB_READ_WRITE_TOKEN` | 운영자 콘솔 서버 저장(없으면 연습 모드만) |
| `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` | 로그인·기기 간 이어 보기. 없으면 로그인 없이 쓰는 예전 방식으로 돌아간다. 테이블·권한은 `supabase/user_state.sql` |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `CRON_SECRET` | 기한 알림(웹 푸시). 매일 한국 시간 09:00 Vercel 크론(`vercel.json` crons)이 `api/_push.js`를 부른다. 테이블·권한은 `supabase/push.sql` (CRON_SECRET의 sha256 해시를 `private.push_key`에 넣는다). 없으면 알림 버튼이 안 보인다 |
| `ANTHROPIC_API_KEY` 또는 `ANTHROPIC_AUTH_TOKEN` | 선택. 운영 배포판에는 넣지 않았다(내장 엔진만) |

```bash
node --test "tests/*.test.js"
```

## 배포

`main`에 병합되면 GitHub Actions(`.github/workflows/deploy-vercel.yml`)가 Vercel 운영 배포를 실행한다. Vercel 프로젝트의 Root Directory는 `demo`이고, 정적 화면과 `demo/api/` 서버 함수가 함께 올라간다. 공공데이터 함수 5개는 Hobby 요금제 함수 개수 제한 때문에 `api/public.js` 하나로 묶었다.

## 범위 제외

- 전세사기 위험 진단 (안심전세 앱 등 기존 서비스로 연결)
- 신청 접수 대행, 기관 시스템 연동
- 공고 자동 수집(크롤링) — 운영자가 원문을 붙이거나 파일을 올린다
- 푸시 알림, 서류 OCR — 기한 알림은 휴대폰 캘린더 구독으로 대신한다
