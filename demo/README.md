# 시연용 정적 페이지

서버·빌드 없이 브라우저로 바로 여는 단일 HTML 시연판 두 개가 있다.

| 파일 | 내용 |
|---|---|
| `index.html` | 계약 전 흐름: 조건 입력 → 신고 의무·지원 자격 확인 → 타임라인, 방 크기 미리보기, 관리자 공고 검수 |
| `app.html` | 계약 후 서비스(새 디자인): 입주 준비·입주 당일·신고·거주·퇴거까지 관리 |
| `admin.html` | 운영자 콘솔: 공고 AI 추출 → 근거 대조 검수 → 승인·버전 발행, AI 자취 코치 지식 관리 (`/admin`) |

## app.html (계약 후 · 새 디자인)

메뉴는 다섯 묶음이다. 휴대폰에서는 아래 탭바(홈·내 주거·주변·생활·지원)와 묶음 안 하위 탭으로 이동한다.

| 묶음 | 해시 | 화면 | 내용 |
|---|---|---|---|
| 홈 | `#home` | 홈 | 인사 배너, 다음 할 일·이번 달 남은 납부·지원 요약, 우리 동네 탐색 지도, 근처 공공시설, 이번 주 가 볼 곳, 입주 한 달 챌린지 |
| 내 주거 관리 | `#contract` | 내 계약 | 계약 정보·집 위치, 시연용 날짜, 홈 화면에 앱 설치, PC→휴대폰 이어서 보기(QR) |
| | `#timeline` | 타임라인 | 계약 전 → 계약 당일 → 입주 준비 → 입주 당일 → 신고·정리 → 지원 신청 → 거주 중 → 만료·퇴거 |
| | `#docs` | 서류함 | 서류 준비 상태 (이 기기에만 보관) |
| | `#moveout` | 퇴거 준비 | 갱신 통지 마감 등 중요한 날짜, 묵시적 갱신·계약갱신요구권·임차권등기명령 안내, 나가기 전 할 일 |
| 주변 탐색 | `#map` | 지도 탐색 | 실제 지도(OpenStreetMap)와 실제 주변 장소, 집 위치(주소 검색·현재 위치·지도에서 고르기), 카카오맵 로드뷰·길찾기 링크 |
| | `#recommend` | 주변 추천 | 공원·운동·공부·생활 편의·맛집·카페, 저장한 곳 |
| | `#infra` | 생활 인프라 | 교통·의료·안전·공공시설까지 도보 시간, 데이터로 만든 요약, 현장 체크 |
| 생활 관리 | `#spend` | 지출 관리 | 이번 달 고정비 구성, 낸 돈·남은 돈, 앞으로 6개월 |
| | `#calendar` | 자취 캘린더 | 기한·월세·공과금·지원금·내 일정, 납부 체크, 휴대폰 캘린더 구독(아이폰·구글)·`.ics`·QR |
| | `#condition` | 집 상태 기록 | 입주 때·퇴거 때 방별 상태 기록, 집주인에게 보낼 문자 만들기 |
| 지원 & 상담 | `#support` | 지원사업 | 전국 시·도, 시·군·구 선택. 승인한 공고는 원문 근거와 함께 판정하고, 공공 API로 받아 온 내 지역 정책·복지 서비스·LH 임대 공고를 목록과 상세로 보여 줌. 승인 공고의 모집 상태는 모집 중·마감·다음 공고 대기. 모르는 조건은 그 자리에서 묻고, 서류마다 받는 곳을 연결 (아래 '지원사업 실제 데이터') |
| | `#coach` | AI 자취 코치 (자취 AI 비서) | 봇 6개: 집주인톡(집주인에게 보낼 문자, 정중하게·짧게, 복사·문자 앱 열기), 고쳐봇(누가 고치는지 판정 + 지금 할 일, 가스 냄새는 안전 순서 먼저), 절약봇(이번 달 고정비 막대 + 받을 수 있는 지원), 권리봇(승인된 지식 카드), 동네봇(가까운 장소, 지도로 이동), 자유 질문(알맞은 봇에게 연결). 봇마다 채팅방이 따로 있다(PC: 왼쪽 방 목록 + 대화, 휴대폰: 목록 → 방). 인사·감사에는 그 방의 봇이 자기소개로 답한다. 모든 봇이 승인된 안내와 내 계약 값만 근거로 쓰고 모르면 멈춤 |

상단 검색창은 주변 장소를 이름·분류·태그로 찾는다(예: 카페, 약국, 전입신고).

계산 규칙

- 기준일은 두 개다. 계약일(C)은 전월세 신고 30일, 입주일(M)은 전입신고 14일과 계약 기간의 기준이다. 기간은 첫날을 빼고 센다(민법 제157조).
- 전입신고는 대항력 때문에 입주 당일을 권장일로, 입주 후 14일을 법정 기한으로 따로 보여준다.
- 전월세 신고 대상이고 기한이 입주보다 뒤면 "전입신고 때 계약서를 함께 내면 신고·확정일자까지 한 번에"를 안내한다. 기한이 입주보다 앞이면 따로 신고하라고 경고한다.
- 지원 금액은 공고마다 따로 보여주고 합산하지 않는다. 캘린더의 지원금 입금은 이용자가 선정된 뒤 직접 켠다.
- 기한 알림은 서버 없이 `.ics` 파일로 휴대폰 캘린더에 넣는다(반복 일정은 RRULE, 알림은 VALARM).
- 물어보기는 승인된 규칙에서 만든 답만 근거와 함께 보여주고, 맞는 규칙이 없으면 답하지 않는다.
- 상단(휴대폰은 내 계약 화면)의 "시연용 날짜"로 입주 전날·당일·10일 후·40일 후 화면을 바로 확인할 수 있다.

## 지원사업 실제 데이터 (공공 API)

지원사업 화면은 두 가지를 함께 보여 준다. 판정 수준이 다르므로 화면에서 구분해 표시한다.

| 구분 | 출처 | 판정 |
|---|---|---|
| 담당자 검수 완료 | 운영자 콘솔에서 승인한 공고 (`rules/seed.js`, `/api/rules`) | 승인된 규칙으로 해당 가능·답하면 판정·확인 필요·해당 안 됨. 조건마다 공고 원문 근거 |
| 검수 전 · 등록 정보 기준 | 온통청년 청년정책 API (`/api/support`) | 공고에 구조화돼 등록된 항목(지역·나이·혼인·취업·학력·대상·연소득)을 대조. 글로 적힌 조건은 금액으로 바꿀 수 있는 것(중위소득 %, 연소득, 무주택, 보증금·월세 상한)만 읽어 견주고, 나머지는 그대로 보여 주며 판정하지 않음 |
| 판정하지 않음 | 복지로 지자체·중앙부처 복지서비스 (`/api/welfare`), LH 분양임대공고 (`/api/lh`) | 목록과 상세, 원문 주소만 |

- 서버 함수는 이용자 정보를 받지 않는다. 지역 코드(법정동코드 앞 5자리)와 분류만 받고, 조건 대조는 이용자 기기에서 한다. 답한 내용은 이 기기에만 저장한다.
- 소득 조건은 이용자에게 "기준 이하인가요"를 묻지 않는다. 가구원 수를 먼저 묻고 그 가구의 기준 금액(2026년 기준 중위소득 × 비율, 만 원 단위)을 보여 준 뒤, 이용자는 월 소득만 넣는다. 견주는 일은 화면이 한다. 혼자 사는 가구는 내 월 소득, 가족과 등본이 같으면 가족 소득 합계로 본다. 연소득 기준은 월 소득 × 12로 견준다. 학자금 지원구간·건강보험료·도시근로자 월평균소득처럼 금액으로 바꿀 수 없는 기준은 판정하지 않고 어디서 확인하는지 알려 준다. 한 번 답한 내용은 '사는 곳·내 정보'에 모이고, 지우면 다시 묻는다.
- 판정은 넷이다: 해당 가능 / 해당 안 됨 / 답하면 판정(아직 답하지 않은 질문만 남음, 그 자리에서 물음) / 확인 필요(공고에서 직접 봐야 하는 조건이 있거나 '모름'이라고 답함). 답이 없다는 것과 확인이 필요하다는 것을 섞지 않는다.
- 무주택·중복 수혜·출생연월은 조건 입력 화면과 같은 값(`S.homeless`, `S.dup`, `S.birth`)을 쓴다. 어느 화면에서 답해도 다른 화면에 그대로 보인다.
- 기준 중위소득 금액은 `support-core.js`의 `MEDIAN_2026`에 있다. 보건복지부 고시 원문과 대조가 필요하다.
- 접수 상태(접수 전·접수 중·상시·끝남)는 화면을 보는 날짜 기준으로 계산한다. 마감일이 올해가 아니면 연도를 붙이고, 마감이 1년 넘게 남은 정책은 'n일 남음' 없이 날짜만 보여 주며 '이번에 할 일'에 올리지 않는다. 마감일이 주말·공휴일이면 알려 준다(`/api/holidays`, 한국천문연구원 특일 정보).
- "이럴 땐 못 받게 돼요"는 등록된 조건(대상 지역, 나이 상한, 미취업·재직, 연소득 상한, 선착순)에서 계산한다. AI를 부르지 않는다.
- 제출 서류는 글을 줄 단위로 나눠 받는 곳(정부24·전자가족관계등록시스템·홈택스·건강보험공단·인터넷등기소·한국장학재단·서류함)을 연결하고, 통장 사본·이체확인증은 은행을 고르면 받는 방법을 보여 준다. 은행 앱 메뉴 이름은 바뀔 수 있다(2026-11-10 정리).
- 목록은 '나에게 맞는 순'이 기본이다. 계약·내 정보에서 상황(월세 세입자, 최근 이사, 나이, 취업·학력)을 짐작해 관련 있는 지원을 위에 두고, 현금으로 받는 지원을 먼저 보여 준다. 자립준비청년·신혼부부처럼 대상이 다른 사업은 뒤로 보낸다. 순서에만 쓰고 판정에는 쓰지 않는다. '마감 빠른 순'은 접수 중이고 마감일이 있는 지원을 가까운 순으로 놓고, 그 뒤에 상시 접수, 접수 전 순으로 놓는다. 어느 탭이든 목록 위에 그 순서가 무슨 뜻인지 한 줄로 적는다.
- 분류마다 지원 형태 상세 탭(현금·바우처 / 대출·보증 / 집·공간 / 교육·프로그램 / 상담·정보)이 있다. 이름과 등록된 '정책 제공 방법'으로 가른다. 같은 기관이 같은 이름으로 여러 번 등록한 정책은 하나로 합친다.
- **내 지역에서 운영하는 사업만 보여 준다.** 온통청년에는 지자체가 자기 사업을 '전국 대상'(전국 시·군·구 코드 전부)으로 등록해 둔 것이 많다(2026-11-11 확인: 지역마다 약 120~130건. 예: 경북 의성군 '청년 지역정착 활성화 사업'이 광주 북구로 조회해도 나옴). 대상 지역 코드만 믿지 않고 등록·주관 기관 이름과 정책 이름에서 어느 시·도, 어느 시·군·구의 사업인지 읽어(`ownerOf`), 중앙부처 사업·내 시·도 사업·내 시·군·구 사업만 남긴다(`forRegion`, 서버 `api/support.js`에서 적용).
  - 다른 시·도가 전국으로 등록한 사업, 같은 시·도의 다른 시·군·구 사업은 뺀다. 누가 운영하는지 읽을 수 없는 전국 등록도 뺀다(정부 산하기관 제외).
  - 전남광주통합특별시는 통합 전 이름(광주광역시·전라남도)이나 정책 이름으로 옛 광주 사업과 옛 전남 사업을 가려, 광주 자치구에는 옛 전남 사업을, 전남 시·군에는 옛 광주 사업을 보여 주지 않는다. 어느 쪽인지 적혀 있지 않은 통합시 사업은 보여 준다.
  - 목록 아래에 몇 건을 뺐는지 적는다. 건수가 많은 것보다 맞는 사업만 보여 주는 것을 먼저 둔다.
- 글로 적힌 조건은 틀리게 읽을 수 있어서 조심해서 쓴다(2026-11-11 전국 30개 시·군·구 1,761건으로 점검).
  - 글에서 읽은 보증금·월세 상한은 넘어도 '해당 안 됨'으로 끊지 않고 '확인 필요'로 둔다. 상한이 두 가지로 적혀 있거나(전세·월세, 수도권·지방) '폐지'된 요건이면 읽지 않는다.
  - '무주택자 우선'처럼 우대로 적힌 것은 필수 조건으로 보지 않는다.
  - 건강보험료로 판정하는 사업은 '중위소득 140%'라고 적혀 있어도 소득 금액으로 판정하지 않고 건강보험공단에서 확인하게 한다.
  - 부모님 가구(원가구) 소득도 보는 사업은 내 소득이 기준 안이어도 '맞음'이라고 하지 않는다.
  - 청년·청년 외·신혼부부 금액이 함께 적힌 연소득 기준은 청년 금액을 쓴다. '8천5백만 원', '1억 3천만원'처럼 합쳐 쓴 금액도 읽는다.
  - 소득 칸에 '-'만 등록된 정책은 소득 조건을 보여 주지 않는다. 나이 하한 0, 상한 99 이상은 제한 없음으로 본다.
  - 서류 칸의 '별도 문의', '누리집 참고' 같은 안내 문장은 서류로 세지 않는다.
- 신청 주소가 등록되지 않은 정책이 많아(점검한 1,761건 중 1,179건) 상세 화면에 온통청년의 그 정책 화면으로 바로 가는 단추를 둔다.
- 온통청년 API는 한 지역 정책(서울 관악구 820건)을 한 번에 받으면 25초를 넘길 때가 있어(2026-11-11 측정 26초) 200건씩 나눠 동시에 받는다. 같은 요청이 가끔 400 오류로 돌아오므로(같은 날 측정, 바로 다시 부르면 정상) 쪽마다 세 번까지 다시 부르고, 화면도 처음 실패하면 한 번은 알아서 다시 받는다. 받은 목록은 6시간 동안 서버 메모리에 둔다.
- 요청 제한은 한 주소당 1분에 180번이다. 막힌 요청은 세지 않는다(세면 계속 누르는 동안 제한이 풀리지 않는다).
- **접수 기간은 공고 원문에서 읽은 것만 마감일로 쓴다** (`/api/period`). 온통청년에 등록된 접수 기간은 사업 기간을 그대로 넣은 값이 많아서다(2026-11-11 점검). 정책마다 등록된 신청·참고 주소 중 공고까지 들어가는 주소를 열어, '신청기간·접수기간·모집기간' 뒤의 날짜를 규칙으로 읽는다(AI 없음). 읽은 문장과 공고 주소를 화면에 함께 보여 준다.
  - 읽지 못하면 '접수 중'이라고 하지 않고 '접수 기간 확인 필요'로 두고, 못 읽은 이유(공고 주소 없음, 페이지가 안 열림, 다른 사업 페이지, 기간이 글로 없음, 지난 해 공고, 기간이 여러 개)를 알려 준다. '이미 끝남'은 등록 값으로도 판단한다.
  - 남은 날, 마감 임박 표시, '이번에 할 일', '마감 빠른 순'의 앞 순서는 공고로 확인한 마감만 쓴다.
  - 공고 주소는 공개 인터넷의 http(s)만 열고 내부망 주소는 막는다. 한 페이지 8초·2MB 한도, 정책 번호로 12시간 기억한다.
- 지역 목록은 `data/regions.js`(법정동코드 API로 만든 표), 공용 로직은 `support-core.js`, 테스트는 `node --test tests/support.test.js`.
- 키가 없으면 해당 목록만 "불러오지 못했어요"로 나오고, 승인된 공고는 그대로 판정한다.

## 내장 AI (외부 API 없이 동작)

AI 기능은 외부 API 키가 없어도 이 기기 안에서 돈다. 규칙은 시스템 프롬프트 두 개에 적혀 있고, 내장 AI는 그 규칙을 코드로 따른다. Claude 키(`ANTHROPIC_API_KEY`)가 있으면 같은 시스템 프롬프트를 Claude에게 주고, 실패하면 내장 AI로 돌아간다.

| 시스템 프롬프트 | 내장 AI | 하는 일 |
|---|---|---|
| `prompts/coach.md` | `coach-core.js` · `assistant-core.js`(봇 6개) | AI 자취 코치. 질문 이해 → 승인 안내 찾기 → 질문 의도(언제·어디서·얼마·서류)에 맞는 문장 고르기 → 내 계약 날짜·금액 넣기 → 근거 붙여 답하기. 앞 질문에 이어지는 되묻기, 위급 상황 공감, 범위 밖·모호한 질문, 지시 무시 요청, 개인 정보, 법률 판단 요청을 따로 처리. 카드에 없으면 답하지 않음 |
| `prompts/extract.md` | `rules-core.js`의 `ruleExtract`·`extractNotes` | 공고 추출기. 22개 항목을 원문 근거 한 줄과 함께 뽑고, 정정 공고·조건 완화·연소득 기준·출생일 기준·세대주·1인 가구·조건부 서류·대출형 지원·공고문 속 지시문을 "AI가 남긴 확인 사항"으로 남김 |

- 코치 답은 생각 단계를 보여 준 뒤 글자 단위로 흘려 보여 주고, "답을 만든 과정"을 펼쳐 볼 수 있다. 질문은 서버로 가지 않는다.
- 두 가지를 한 번에 묻는 질문, "오늘 뭐 해야 돼?"(내 타임라인의 지금 챙길 일), 띄어쓰기 없는 질문에 답한다. 카드와 흔한 낱말('신고')만 겹치고 핵심 주제가 승인 안내에 없으면("층간소음 신고") 엉뚱한 카드로 답하지 않고 멈춘다.

### 품질 평가 (운영자 콘솔 '품질 평가')

`rules/evals.js`의 평가 세트를 지금 승인본으로 바로 돌린다(`eval-core.js`). 지식을 고치거나 공고를 승인한 뒤 다시 돌려 전에 맞던 질문이 깨지지 않았는지 본다.

| 세트 | 내용 | 결과 (2026.11.11) |
|---|---|---|
| 코치 · 기본 질문 | 실제 자취생 말투 63문항 (되묻기·두 질문·범위 밖·지시 무시·모르는 주제 포함) | 63/63, 틀린 답 0 |
| 코치 · 처음 보는 질문 | 엔진을 다듬을 때 보지 않고 떼어 둔 30문항 | 30/30, 틀린 답 0 |
| AI 비서 · 봇 연결 | 질문 41개가 알맞은 봇에게 가고 답에 필요한 내용이 있는지 | 41/41 |
| 페르소나 | 계약 조건이 다른 자취생 7명(첫 자취 대학생, 전입신고를 놓친 사회초년생, 반전세, 소액 계약, 만료를 앞둔 직장인, 지원 나이 초과, 계약 두 달 뒤 입주)이 묻는 30문항. 내 조건과 다른 안내가 섞이면 실패 | 30/30, 조건과 다른 답 0 |
| 말투 페르소나 | 같은 내용을 줄임말·오타(ㅈㅇㅅㄱ), 걱정 많은 장문, 부모, 영어 섞임(rent·deadline), 격식체로 묻는 16문항 | 16/16 |
| 공고 추출 | 시연 공고 3개의 정답 38개 항목 | 38/38 |

'틀린 답'은 엉뚱한 카드로 답했거나 답하면 안 되는 질문에 답한 경우, '답하지 않음'은 답할 수 있었는데 멈춘 경우(안전한 실패)다. 테스트가 기본 세트 95% 이상·틀린 답 0개를 지킨다.
- 운영자 콘솔 "시스템 프롬프트" 화면에서 두 프롬프트를 보고 복사·내려받을 수 있다. 코치 프롬프트에는 지금 승인된 지식·공고가 모두 들어간다.

## 운영자 콘솔 (admin.html) — 공고 검수 + AI 코치

공고가 이용자 화면에 반영되기까지:

1. **추출** — 공고 원문을 붙이거나 PDF·HWPX·TXT 파일을 올리면(글자는 브라우저에서 뽑음) AI가 판정 항목 22개(나이·소득·보증금·월세 상한, 접수 기간, 지원 금액, 제출 서류, 중복 불가 등)를 **항목마다 근거 문장과 함께** 뽑는다. AI 키가 없거나 실패하면 규칙 기반 추출로 대신한다.
2. **자동 점검** — 근거 문장이 원문에 실제로 있는지, 값의 숫자가 근거와 맞는지(8천만 원 → 8000 같은 환산 포함), 목록 항목이 원문에 있는지, 필수 항목이 비었는지, 지난 승인본과 무엇이 달라졌는지 본다.
3. **사람 검수** — 표시된 항목만 원문과 나란히 대조해 하나씩 확인한다. 원문 줄을 누르면 그 줄을 쓴 항목으로, 항목 인용을 누르면 원문 줄로 이동한다. 원문을 드래그해 근거를 바꿀 수 있다. AI가 남긴 확인 사항(애매한 조건, 정정 흔적 등)도 확인해야 한다.
4. **영향 확인** — 지난 승인본과 다른 점, 예시 이용자 6명의 판정이 어떻게 바뀌는지(대상자 시뮬레이션), 이용자 화면 미리보기를 본다.
5. **승인·발행** — 모두 확인해야 승인 버튼이 켜진다. 승인하면 새 버전(v2, v3…)으로 발행되고 검수자·시각·바뀐 항목이 변경 기록에 남는다. 지난 버전으로 되돌릴 수 있다. 반려는 사유를 남긴다.

AI 자취 코치:

- **코치 지식**: 운영자가 승인한 지식 카드(법령·공식 안내 근거 필수)와 승인된 공고만 근거로 쓴다. "코치 시험해 보기"로 질문마다 어떤 카드를 읽는지 확인한다.
- **답 못 한 질문**: 코치가 멈춘 질문(질문 글만, 개인 정보 없이)이 모인다. 근거를 찾아 지식 카드로 만들면 다음부터 답한다.
- 이용자 화면은 질문과 앱이 계산한 날짜·금액만 보낸다. 이름·주소·집 위치는 보내지 않는다.

모드:

| 모드 | 조건 | 저장 위치 |
|---|---|---|
| 공유 저장소 | `ADMIN_TOKEN`·`BLOB_READ_WRITE_TOKEN` 설정, 운영자 코드로 로그인 | Vercel Blob(비공개). 모든 이용자에게 반영 |
| 서버 메모리 | `ADMIN_TOKEN`만 설정 | 서버 인스턴스 메모리 (재시작하면 사라짐, 시험용) |
| 연습 모드 | 운영자 코드 없음 | 이 브라우저 `localStorage`. 같은 브라우저의 이용자 화면에만 반영 (시연용) |

시연 공고 3개(청년월세 2차 모집·임차보증금 이자 지원·중개보수 정정 공고)는 모두 시연용 예시 원문이다. 시연 공고의 AI 추출 결과는 처음 한 번만 AI를 부르고 저장해 둔다.

규칙 엔진 `rules-core.js`·`coach-core.js`는 브라우저와 서버가 같이 쓴다. 테스트(25개): `node --test tests/rules.test.js`

## 시연판의 한계

- 지원 사업 금액·자격 조건과 관리자 화면의 "지난 공고" 변경 이력은 예시 값이다. 공고 원문과 대조 전이다.
- 걸리는 시간은 직선거리 ÷ 분당 67m라서 실제 도보 경로보다 짧게 나올 수 있다. 장소 정보는 OpenStreetMap에 등록된 만큼만 나온다.
- 로드뷰는 화면에 넣지 않고 카카오맵 공개 링크로 연다(화면 안에 넣으려면 카카오 지도 JavaScript 키와 도메인 등록이 필요).
- 알림 발송(푸시), 서류 OCR·요건 점검은 동작하지 않는다. 알림은 휴대폰 캘린더 구독·.ics의 알림으로 대신한다.
- 내장 AI는 언어 모델이 아니라 시스템 프롬프트의 규칙을 따르는 엔진이라, 승인된 안내에 있는 문장을 골라 다듬어 답한다. 처음 보는 표현의 질문은 못 알아들을 수 있고, 그때는 답하지 않고 운영자에게 질문을 넘긴다.
- 공고 수집(크롤링)은 하지 않는다. 운영자가 원문을 붙이거나 파일을 올린다. HWP(구형)는 HWPX·PDF로 저장해야 읽는다. 스캔 PDF는 읽지 못한다.
- 소득 기준은 기준 중위소득 % 기준만 판정한다. 연소득 금액 기준 등은 AI 확인 사항으로 남기고 판정에 넣지 않는다.
- 입력값과 체크 기록은 브라우저 `localStorage`에만 저장한다.

## 배포

Vercel 프로젝트의 Root Directory를 `demo`로 두면 정적 파일과 `api/` 함수가 함께 배포된다. 빌드 과정은 없고, `package.json`의 의존성(`@anthropic-ai/sdk`, `@vercel/blob`)만 설치된다. `vercel.json`이 첫 주소(`/`)를 `app.html`로, `/cal.ics`를 `api/calendar`로 보낸다.

운영 주소: https://jachwi-navi.vercel.app
