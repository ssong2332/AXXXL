# 지원사업 브랜치 통합 안내 (`feat/support-api`)

통합 담당자가 이 브랜치를 다른 팀원 브랜치와 합칠 때 보는 문서. 2026-11-11 기준 (PR #13 반영 후).
기능 설명은 `demo/README.md`의 '지원사업 실제 데이터 (공공 API)'에 있고, 여기에는 합치는 데 필요한 것만 적는다.

### 무주택·중복 수혜·나이 (PR #13과 맞춤, 11/11)

git이 충돌로 알려 주지 않던 부분이다. 지금은 아래처럼 맞춰 두었다.

- 무주택·중복 수혜 답은 조건 입력과 같은 `S.homeless`, `S.dup` 하나만 쓴다 (`yes`·`no`·`unknown`). 지원사업 화면 안에서 답해도 같은 값에 저장되고, 조건 입력에도 그대로 보인다
- 값이 없음 = 아직 답하지 않음, `unknown` = 모른다고 답함. 둘을 섞지 않는다
  - `FRESH`에 기본값을 두지 않는다. 예전에는 `'unknown'`이 기본값이라 이 질문을 본 적 없는 예전 사용자도 '모름'으로 판정돼 모든 지원이 '확인 필요'로 보였다
  - `engine.js` `toUser()`는 값이 없으면 그대로 넘긴다. `rules-core.js`는 원래 설계대로 값이 없으면 판정에서 뺀다
  - 조건 입력·온보딩 선택칸 맨 앞에 '아직 안 정함'. 고르면 값을 지운다
- 지원사업 화면 판정은 넷: 해당 가능 / 해당 안 됨 / **답하면 판정**(아직 답하지 않은 질문만 남음) / **확인 필요**(공고에서 직접 봐야 하는 조건이 있거나 '모름'이라고 답함). `support-core.js` `verdict()`
- 예전 저장값 맞추기 `migrate()`: 지원사업 화면이 따로 받던 무주택 답(`S.sup.self.homeless` `y`·`n`)은 `S.homeless`가 비어 있을 때만 옮긴다. 시연용 예시는 비어 있으면 예시 인물 값(`DEMO`)으로 채운다
- 나이: 지원사업 화면도 `curAge()`(출생연월 → 계약일 기준 만 나이)를 읽는다. 나이 질문은 출생연월로 받아 `S.birth`에 저장. 생일 달이라 만 나이를 정할 수 없으면 다시 묻지 않고 확인 필요
- 남은 것: 박수홍 '자격 판정' 화면은 `rules-core.js` 설계 그대로라, 답하지 않은 무주택은 줄에 '직접 확인'으로 보이고 전체 판정에서는 빠진다(해당 가능). 이 화면에도 '답하면 판정'을 둘지는 정하지 않았다
- `S.dup`은 답 하나를 모든 공고의 '함께 받을 수 없는 지원'에 똑같이 쓴다. 지금 예시 공고에는 이 조건이 청년월세 하나뿐이다

## 합친 뒤 확인

1. `node --test "tests/*.test.js"` (전체)
2. `node demo/dev-server.js` 실행 후 `http://localhost:4173/app.html#support`
   - 지역을 바꾸면 목록이 다시 뜨는지
   - 사업을 누르고 '공고 보기'가 **기관 첫 화면이 아니라 그 사업 공고**(또는 온통청년의 그 정책 화면)로 가는지
   - `#coach` 등 다른 화면이 그대로 열리는지
3. 배포판에서는 `/api/support?zip=11620`이 `ok: true`를 돌려주는지 (키가 없으면 `reason: "nokey"`)

## 알아 둘 것

- 서비스 실행 중 AI 호출은 없다. 공고 글은 규칙으로만 읽는다.
- 키는 `demo/.env`(커밋 제외)와 Vercel 환경변수에만 둔다.
- '공고 보기'가 갈 곳은 `support-core.js`의 `noticeLink()` 한 곳에서 정한다. 등록된 주소가 기관 대문뿐이면 온통청년의 그 정책 상세 화면으로 보낸다. 게시판 목록 주소처럼 대문은 아니지만 글 하나를 가리키지 않는 주소는 걸러 내지 못한다.
- 승인된 예시 공고(`rules/seed.js`)의 '공고 원문' 단추는 서울주거포털 첫 화면으로 간다. 시연용 예시라 그대로 두었다 (공고 검수 담당 영역).
